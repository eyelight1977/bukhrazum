# БухРазум 0.3.2

Помощник проверки КФЗ по первичным и расчетным документам. Команда «УмЗаРазум», Хакатон МФТИ.

Загрузи PDF КФЗ и подтверждающие документы, укажи договор, строку и период. Помощник извлечёт значения, сопоставит документы, рассчитает ожидаемые суммы и покажет расхождения с основаниями. Исходные файлы сохраняются копиями. Внешние сервисы, API-ключи и интеграции с 1С не нужны.

## Результат проверки

Одна компактная таблица: показатель КФЗ, значение в КФЗ, ожидаемое по документам, расхождение, статус, пояснение. Сначала показаны 0200, 0300, 0800, 0900 и общий итог.

Под статьёй раскрой «Первичные и расчетные документы — N»: видны все включённые слагаемые и их сумма. «Показать подтверждающий фрагмент» открывает закрываемую область просмотра. Выбирай источник, «Фрагмент»/«Контекст», масштаб −/+. Для XLSX видны лист и адреса ячеек, для DOCX — абзац/таблица, для PDF/изображений — выделенная область страницы. Office показывается структурно, без полного воспроизведения оформления. Закрытие возвращает к таблице с сохранённой расшифровкой.

Общий итог раскрывает четыре статьи со ссылками, без повторения списка всех документов. Исключённые документы показаны отдельно с причинами. Детализация КФЗ и арифметические формулы находятся в раскрываемых подробностях. После них — ограничения и итоговое заключение. «Открыть отчёт» даёт тот же формат в самодостаточном HTML со встроенными изображениями и просмотром без интернета; сохрани страницу браузером. JSON содержит данные и историю решений. HTML поддерживает просмотр, уточнения вносятся в приложении. Если ранее сохранённый экспорт отличается, новый файл получает имя с хешем; предыдущий не перезаписывается.

## Правила расчётов и статусов

- Разница = значение КФЗ минус ожидаемое по документам; деньги — `Decimal`, сравнение до копейки.
- Связь документов — договор, период и содержание; имя файла не определяет сумму/статью. Дубли, другой договор/период исключаются с причиной. Точная копия КФЗ не является независимым источником.
- Зарплата и взносы проверяются на покрытие месяцев. Несколько месячных расчётов требуют уточнения, не суммируются безусловно.
- Арифметика КФЗ: 5=6+9, 6=7+8, 10=11+14, 11=12+13, 17=5+10+15+16. Источник — «Расчёт»; подтверждающие документы для сложения не нужны. Успех арифметики не подтверждает суммы документами.
- Объединение 8+9 сверяется с соответствующими начислениями ведомостей; 13+14 не выводится из предполагаемого тарифа/общих взносов. Без независимой детализации ожидаемая сумма недоступна. Подтверждение объединения не подтверждает части отдельно.
- Неизвестное значение не равно нулю. Если значение требует подтверждения, помощник предлагает сверить выделенное поле КФЗ с документом; зависимые итоги остаются непроверенными. Численное совпадение само по себе не снимает эту блокировку.
- Подтверждение агрегата не требует независимых документов для каждой внутренней составляющей, если сама агрегированная сумма и необходимые значения КФЗ проверены.
- Пользовательские решения добавляются отдельно от исходного OCR; сохраняется вся история. Изменение общей суммы документа не устанавливает новую внутреннюю разбивку.
- Расхождение статьи и его переход в общий итог считаются одной группой; денежный ущерб повторно не складывается.
- Расхождения → вернуть на доработку; неуточнённые входы → сначала уточнить. При совпадении проверенных сумм и непроверенной детализации действует временная рекомендация подписать с оговорками. Заказчик ещё должен подтвердить это правило; в форме доступен строгий вариант.

## Окружение

Docker Desktop/Engine с работающим Linux-движком. Python 3.12, Node.js 24, точные пакеты — `requirements.txt` и `package-lock.json`. Tesseract.js/core 7, локальные rus/eng модели с SHA-256 и лицензией в `app/models/`. После сборки OCR не скачивает модели; Node-процесс OCR блокирует HTTP(S), fetch, DNS и сокеты. Сборка загружает официальные базовые образы и пакеты.

Поддержанная проверкой архитектура: **Linux/arm64** в Docker Desktop на Mac Apple silicon. Зависимости Intel/amd64 и Rosetta не требуются. Windows, PowerShell и Linux/amd64 не запускались; приведённые ниже PowerShell-команды подготовлены, но не проверены исполнением. Другие платформы не заявлены как проверенные.

## Docker: macOS/Linux

Из корня распакованного комплекта:

```sh
docker build --pull --no-cache -t bukhrazum:0.3.2 .
mkdir -p work/container results/container
docker run --name bukhrazum -d --user "$(id -u):$(id -g)" -p 127.0.0.1:8765:8765 \
  -v "$PWD/work/container:/app/work" -v "$PWD/results/container:/app/results" bukhrazum:0.3.2
```

Открой <http://127.0.0.1:8765>. Остановка `docker stop bukhrazum`, повторный запуск `docker start bukhrazum`; журнал `docker logs bukhrazum`; состояние `docker inspect --format='{{.State.Health.Status}}' bukhrazum`. SQLite, копии, OCR и решения остаются в подключённых папках. Для новой независимой приёмки используй другое имя и новые папки, старые не очищай. Compose не нужен — один контейнер.

## Docker: PowerShell / Windows — исполнение не проверено

Нужен Docker Desktop в режиме Linux containers. Из корня комплекта:

```powershell
docker build --pull --no-cache -t bukhrazum:0.3.2 .
New-Item -ItemType Directory -Force work/container, results/container | Out-Null
$projectPath = (Get-Location).Path
docker run --name bukhrazum -d -p 127.0.0.1:8765:8765 --mount "type=bind,source=$projectPath/work/container,target=/app/work" --mount "type=bind,source=$projectPath/results/container,target=/app/results" bukhrazum:0.3.2
Start-Process "http://127.0.0.1:8765"
docker logs bukhrazum
docker stop bukhrazum
docker start bukhrazum
```

На Windows/amd64 будет собран другой архитектурный образ; он требует отдельной сквозной проверки. Не используй это как свидетельство проведённой приёмки.

## Два воспроизводимых примера

В `examples/01-coincidence/` и `examples/02-discrepancy/` находятся полностью синтетические PDF, DOCX, XLSX и `expected.json`. В них нет документов заказчика. Для ручной проверки загрузи `report.pdf` как КФЗ, остальные DOCX/XLSX — как подтверждающие, строка `1 этап 2026`, договор `77/01/26-01`, период январь 2026. Ожидаемые результаты и оговорки — [сценарии](docs/use_cases.md).

Автоматическая проверка на запущенном контейнере (создаёт только новые тестовые проверки):

```sh
docker exec bukhrazum python -m unittest discover -s /app/tests -p 'test_*.py' -v
```

Для этой команды тесты должны быть подключены при запуске: добавь `-v "$PWD/tests:/app/tests:ro"`; для примеров также `-v "$PWD/examples:/app/examples:ro"`. Затем:

```sh
docker exec bukhrazum python /app/tests/synthetic_examples.py --url http://127.0.0.1:8765
```

Ожидаемые значения используются только тестом, приложение их не читает. Автотест подтверждает сомнительный OCR только в созданных им проверках после проверки распознанных чисел. Это не отменяет ручное подтверждение при обычной работе.

Локальный запуск без Docker: после отдельной установки перечисленных Python/npm-зависимостей и наличия Python 3.12/Node 24 запусти `sh run_local.sh`. Скрипт использует `.venv/bin/python` либо `python3`, не устанавливает пакеты и не ищет скрытые среды. Остановка Ctrl+C. Рекомендуемый проверенный путь — Docker.

## Настройки и ограничения

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| APP_HOST | 127.0.0.1; в контейнере 0.0.0.0 | HTTP bind; наружу опубликован только loopback-порт |
| APP_PORT | 8765 | Порт |
| APP_DATA_DIR / APP_RESULTS_DIR | work / results | Копии/SQLite и экспорт |
| OCR_CONFIDENCE_THRESHOLD | 85 | Балл 0..100, экспериментальный порог, не вероятность ошибки |
| OCR_NODE_BIN / OCR_NODE_MODULES | node / стандартное разрешение npm | Явный выбор имеющегося Node/каталога пакетов |
| APP_PYTHON_BIN | .venv или python3 | Только локальный launcher |

КФЗ — одностраничная форма с 17 столбцами; другие формы не проверены. До 100 подтверждающих файлов, 20 МБ на файл/60 МБ на JSON-запрос с base64, 20 страниц PDF, 8 млн пикселей на растровый вход/отрендеренную страницу, период до двух лет. ZIP Office ограничен 2500 записями/100 МБ распакованного содержимого; XLSX читается до 10000 строк/100 столбцов. Произвольные Excel-формулы не вычисляются: используются исходные начисления, а не пустой кэш SUM. OCR и семантические правила не универсальны, неоднозначности требуют решения пользователя.

**Приложение однопользовательское. Не публикуй его текущий HTTP-порт напрямую в интернет.** Встроенной авторизации/разделения проверок по посетителям нет. Предложение ограниченного размещения и отдельная проверка защиты нужны до публикации; готовый Docker-образ сам по себе не решает эту задачу.

### Уточнение представления 0.3.2

В бухгалтерских пояснениях и статусах нет баллов OCR, порогов и комментариев о проходах распознавания. Показаны результат сверки и необходимое действие: подтвердить выделенное значение. Техническая диагностика сохраняется в исходном результате/JSON, правила подтверждения не меняются. Фрагмент КФЗ сразу показывает шапку выбранного поля, номера столбцов и выбранную строку с выделенной суммой; заголовок выделен синим, значение — жёлтым. Масштаб и контекст доступны.

Формат отчёта зафиксирован в версии 0.3.2. Пользовательский статус, требующий подтверждения значения: «Подтвердите число». Репозиторий: https://github.com/eyelight1977/bukhrazum .
